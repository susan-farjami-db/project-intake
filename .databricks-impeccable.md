## Design Context

- **Target audience**: IT / AI & Analytics reviewers
- **Surface type**: Databricks App (FastAPI + React)
- **Use case**: Submit an AI Task Force request, classify it as AI / Data / Analytics / Other, and edit the request list
- **Light or dark theme**: Light (review sessions on a projector or laptop)

## Design Brief

### User journey
1. Open the AI Task Force intake app.
2. Submit a request on the intake form using the standard intake fields.
3. See a suggested intake type and likely duplicates while typing.
4. Review and update requests on the editable list (Open / In Progress / Closed).
5. Open a record to edit the remaining fields.

### Screens
1. Intake form — standard intake fields, live classification, duplicate scan
2. Requests — editable list with status update
3. Request detail — full record edit and related matches

### Out of scope
External ticketing and approval workflows. Requests persist in Lakebase. Databricks `ai_classify` is used when `DATABRICKS_SQL_WAREHOUSE_ID` is set; otherwise a label-matched heuristic is used.
